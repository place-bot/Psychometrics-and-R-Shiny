# 参数量、显存与训练成本

## 1. 一个 Transformer 投影

对 \(d\times d\) 的 Q 投影，LoRA rank \(r\) 参数为 \(2dr\)。若每层同时适配 Q 与 V：

\[
\text{params per layer}=4dr.
\]

若有 \(L\) 层：

\[
|\Theta|=4Ldr.
\]

GPT-3 175B 中 \(L=96,d=12288,r=4\)：

\[
4\cdot96\cdot12288\cdot4
=
18{,}874{,}368,
\]

约 18.9M；FP16 原始数据约 37.7MB，与论文约 35MB 的数量级一致。

## 2. 为什么训练显存下降

冻结参数仍需保存并参与前向；省下的是：

- 基座权重梯度；
- Adam 一阶、二阶状态；
- 部分反向传播中与权重梯度相关的存储和通信；
- 每任务完整 checkpoint。

基座模型本身不会消失，因此 LoRA 并不让一个原本完全装不下的模型自动装下。量化基座的 QLoRA 属于后续扩展。

## 3. 激活显存

长序列、大 batch 的激活仍可能占主导。LoRA 主要减少可训练参数和 optimizer state，不能直接消除 attention \(O(n^2)\) 激活或所有反向激活。

## 4. 训练 FLOPs

低秩分支增加

\[
O(r(d_{\text{in}}+d_{\text{out}}))
\]

乘法，且无需计算 \(W_0\) 的权重梯度。仍需把梯度通过 \(W_0\) 传给更早层的激活，所以基座反向计算不会全部消失。

## 5. 多任务存储

\(T\) 个全量模型约需

\[
T|\Phi_0|.
\]

共享基座加 LoRA：

\[
|\Phi_0|+\sum_{t=1}^{T}|\Theta_t|.
\]

任务越多，共享收益越大。

## 6. 参数效率与总资源

报告 LoRA 成本时应分别说明：

- 总模型参数；
- 可训练参数；
- optimizer state；
- checkpoint；
- 峰值显存；
- 训练吞吐；
- 推理时是否合并；
- 基座精度与量化方式。

只报告“训练参数百分比”无法完整描述资源。
