# 局限、结论与通向 GPT-3

## 1. 方法局限

### 1.1 任务学习是间接的

模型对所有 token 一视同仁。对事实答案、HTML 残留、修辞性段落和错误陈述使用同一种预测损失：

\[
\mathcal L
=
-\sum_t\log p(x_t\mid x_{<t}).
\]

目标没有显式表达事实性、帮助性、安全性或用户意图。

### 1.2 任务格式敏感

`TL;DR:`、`A:`、示例分隔符和候选打分方式都会影响结果。论文尚未系统研究 prompt 变体、示例顺序与随机性。

### 1.3 单向上下文

当前位置只能读取左侧文本。分类和双向理解任务常从 BERT 式双向 encoder 获益；GPT-2 报告也把单向表示的效率上限列为待研究问题。

### 1.4 输出可靠性

官方模型卡明确提醒：模型不会区分事实与虚构，不支持要求内容为真的用途。流畅性可能掩盖细微矛盾与错误。

### 1.5 数据与偏差

WebText 继承网页和筛选社区的偏差，完整语料未公开。模型可能生成刻板印象、有害内容和个人信息式文本。

### 1.6 复现范围有限

官方仓库提供推理模型，但缺少完整训练数据和训练代码。研究者可以复现结构与生成，却无法精确重建 WebText 训练实验。

## 2. 实验局限

- 不同任务使用不同 prompt、解码和后处理；
- 一些 zero-shot 实验含上下文示例；
- 小数据集结果方差较大；
- 网页预训练与 benchmark 存在表面重叠；
- 四个模型规模不足以严密刻画 scaling law；
- 与监督 SOTA 的数据、计算和输出约束并不对称。

## 3. 论文真正改变了什么

在 GPT-2 之前，预训练模型常被理解为可迁移表示的初始化器。GPT-2 展示了另一种接口：

\[
\text{任务调用}
=
\text{把任务写进上下文}
+
\text{让同一 LM 继续生成}.
\]

它把 prompt 从“生成开头”提升为“任务描述接口”。即使当时性能还不稳定，这一接口直接通向后来的 in-context learning。

## 4. GPT-2 到 GPT-3 的连续变化

| 维度 | GPT-2 | GPT-3 |
|---|---|---|
| 最大参数量 | 约 1.5B | 175B |
| 上下文长度 | 1024 | 2048 |
| 数据 | 约 40 GB WebText | 约 300B 训练 token 的混合语料 |
| 任务设置 | 广义称 zero-shot | 明确区分 zero/one/few-shot |
| 研究重点 | 多任务行为开始出现 | 规模如何增强 in-context learning |
| 污染检查 | 8-gram Bloom filter | 13-gram 为主的 clean subset 分析 |

GPT-3 沿用 GPT-2 的自回归架构、pre-LN 和可逆 tokenization，主要通过更大模型、更大数据、更多训练以及系统化上下文评测推进研究。

## 5. 结论

GPT-2 的结论可以压缩成三个层次：

1. 大规模、多样文本上的 next-token prediction 能学到跨域语言规律；
2. 自然文本里的任务示范可以转化为没有参数更新的任务行为；
3. 这些行为通常随模型容量增强，但离稳定、可靠的通用系统仍有明显距离。

下一篇 GPT-3 的核心问题正是：把模型规模再扩大两个数量级后，上下文中的少量示例能否成为一种更强、更系统的快速适配机制。
