# Byte-level BPE：任何字符串都能编码

## 1. 输入表示的目标

通用语言模型希望对任意字符串赋概率。若词表只收录常见单词，就会出现未知词：

\[
\text{unseen word}\longrightarrow \langle\mathrm{UNK}\rangle.
\]

多个不同字符串被压成同一个 UNK 后，原始文本无法恢复，模型也无法准确生成姓名、代码、拼写变体和罕见字符。

## 2. 三种粒度的权衡

| 粒度 | 优点 | 代价 |
|---|---|---|
| word | 序列短、常见词语义完整 | 词表巨大、OOV |
| character/byte | 覆盖任意字符串 | 序列长、常见词结构重复学习 |
| subword | 高频片段整体表示、低频词拆开 | 需要学习分词词表 |

GPT-2 采用 byte-level BPE：基础原子是 UTF-8 字节，之后用 BPE 把频繁字节序列合并为更长 token。

## 3. 为什么基础词表是 256

一个字节有

\[
2^8=256
\]

种取值。任何 Unicode 字符串都能先编码成 UTF-8 字节序列。因此只要 256 个基础符号就具备完备覆盖；BPE 合并只负责提高压缩效率。

论文指出，若直接以所有 Unicode code point 为基础，基础词表会超过 13 万，还没有加入任何多字符 token，成本过高。

## 4. 可逆字节映射

官方 `encoder.py` 的 `bytes_to_unicode()` 建立双射：

\[
b\in\{0,\ldots,255\}
\quad\leftrightarrow\quad
u_b\in\text{可打印 Unicode 符号集合}.
\]

这样 BPE 实现仍可在字符串上工作，同时保留原始字节。解码时依次执行：

\[
\text{token IDs}
\to
\text{BPE 字符串}
\to
\text{字节}
\to
\text{UTF-8 文本}.
\]

## 5. BPE 合并

设当前单词被拆成符号序列：

\[
(s_1,s_2,\ldots,s_m).
\]

算法反复寻找在训练语料中排名最靠前的相邻 pair，并将它合并。简化示例：

```text
l o w e r
lo w e r
low e r
low er
lower
```

常见单词可能成为一个 token；罕见词仍可由多个 subword 或字节组成。

## 6. 为什么不能无条件跨类别合并

论文发现，直接在字节串上贪心合并会为 `dog`、`dog!`、`dog?` 等表面形式浪费多个词表槽位。作者限制跨字符类别的合并，并对空格做例外处理，以减少标点变体造成的碎片化。

官方正则把文本大致分成：

- 英文缩写后缀；
- 可选前导空格加字母串；
- 可选前导空格加数字串；
- 可选前导空格加符号串；
- 空白串。

## 7. 词表与边界

报告给出的词表大小为 50,257。它通常可以理解为：

\[
256\ \text{个字节基础符号}
+
50{,}000\ \text{次左右的合并结果}
+
1\ \text{个特殊 token}.
\]

GPT-2 使用 `<|endoftext|>` 标记文档边界。空格常被吸收到后一个 token 中，因此同一个词在句首和前有空格时可能对应不同 token 序列。

## 8. 它解决了什么，又留下什么

它提供：

- 无 OOV 的可逆编码；
- 对拼写、网址、代码和多语言字符的基础覆盖；
- 比纯字节模型更短的序列。

它仍有局限：

- 英语中心语料学到的 merge 对其他文字压缩效率较低；
- token 边界不等于词法或语义边界；
- 同一字符在 UTF-8 中可能占多个字节；
- 计算成本由 token 数决定，不同语言的实际成本不同。
