# WebText：数据如何构造

## 1. 为什么不直接使用 Common Crawl

作者需要一个领域多样、规模较大、又包含相对完整自然文本的语料。Common Crawl 足够大，但原始网页中有导航、模板、广告、乱码、SEO 文本和低质量页面。若完全围绕某个下游任务筛数据，又会预先泄露任务偏好。

WebText 采用人工群体筛选的代理信号：某个网页链接在 Reddit 上至少获得 3 karma，说明至少有一些用户认为它值得分享或阅读。

## 2. 构建流程

论文描述的流程可以写成：

```text
Reddit 外链
   ↓ 至少 3 karma
约 4500 万个链接
   ↓ 下载外链页面，不把 Reddit 评论作为正文
HTML 响应
   ↓ Dragnet + Newspaper 抽取正文
文本文档
   ↓ 去重、启发式清洗、时间截断
WebText 实验版本
```

实验所用初版数据满足：

- 不包含 2017 年 12 月之后创建的链接；
- 去重和清洗后略多于 800 万篇文档；
- 总计约 40 GB 文本；
- 为减少与常见 benchmark 的重叠，主动移除了 Wikipedia 文档。

## 3. 数据为什么能支持多任务假设

单一新闻域主要教会模型新闻写作分布。跨网站语料还可能包含：

- 教程与操作步骤；
- 论坛式问答；
- 双语引文；
- 文章与 TL;DR 摘要；
- 对话与访谈；
- 表格、列表和半结构化页面。

不同文档格式把多种 \(p(\text{output}\mid\text{input},\text{task})\) 的示例混入同一个训练分布。

## 4. 人工筛选信号的偏差

karma 不是文本质量的客观标签。它受到社区人口、兴趣、时间、语言和平台规则影响。因此 WebText 会继承：

- Reddit 用户与外链发布者的选择偏差；
- 英语互联网与美国中心的内容偏差；
- 热门主题过度代表；
- 被链接网站的编辑和商业偏差；
- 原始网页中的事实错误、刻板印象与有害文本。

官方模型卡进一步说明，WebText 来源是 Reddit 用户发布的外链页面正文，不等于直接使用 Reddit 站内文本。

## 5. 数据集没有公开带来的验证困难

GPT-2 官方发布了模型、代码、输出样本数据集和 WebText 高频域名列表，但没有发布完整 WebText 训练集。研究者难以完全复现：

- 具体抓取清单；
- 页面抽取版本；
- 清洗与去重规则；
- 每条训练样本；
- benchmark 污染的完整审计。

因此“官方代码可运行推理”和“论文训练流程可完全复现”是两个不同层面的判断。

## 6. WebText 与模型能力的关系

论文的因果主张需要谨慎：实验同时增加了数据规模、多样性、模型参数量、上下文长度和训练计算。现有设计能显示整个系统随规模改善，却很难把收益精确分解为：

\[
\text{收益}
=
\text{数据质量}
+
\text{数据多样性}
+
\text{参数规模}
+
\text{优化变化}
+
\text{评测格式效应}.
\]

这也解释了为什么后续 scaling law、数据消融和污染研究成为独立方向。
