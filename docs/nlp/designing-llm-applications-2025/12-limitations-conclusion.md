# 局限、结论与未来更新

## 1. 这本书适合解决什么

它提供一张覆盖 LLM 生命周期的地图，尤其适合：

- 已理解基本深度学习，想连接模型与应用的人；
- 需要在 RAG、fine-tuning、agent 和 inference 之间做选择的人；
- 希望理解失败来源，而非只复制 demo 的团队；
- 想把单模型原型升级为多组件系统的研究者。

## 2. 阅读时需要补充什么

### 快速变化的软件接口

模型、框架、许可证与 API 会继续更新。书中稳定价值是原理与决策维度；具体命令应回到当前官方文档。

### 单篇论文证据

一本综合书籍横跨很多主题，无法替代每个方法的原论文、实验和代码。本网站通过 Transformer、LoRA、GPT、Llama 2 等单篇精读补足证据。

### 领域评价

通用 benchmark 无法代替医疗、金融、教育与 CAT 的效度、公平性和风险评价。

## 3. 原型到生产的检查表

```text
任务定义
→ 数据与隐私
→ tokenizer 与模型版本
→ 基线与评价集
→ prompt / RAG / fine-tuning 选择
→ 推理成本与 serving
→ tool 权限与 guardrail
→ tracing 与失败分析
→ 线上监控与回滚
```

## 4. 五个核心决策

1. **知识放在哪里**：参数、prompt、检索库或工具？
2. **行为怎样改变**：提示、SFT、偏好优化还是程序约束？
3. **正确性怎样验证**：指标、证据、执行器还是人工？
4. **成本怎样控制**：小模型、cascade、cache、量化还是并发？
5. **风险由谁负责**：模型拒答不能替代系统权限与治理。

## 5. 对 tokenizer 推荐语的最终解释

推荐这本书深入 tokenizer 是合理的，因为 Chapter 3 不只列出 BPE 和 WordPiece，还把它们放在 vocabulary、normalization、pre-tokenization 和 special token 的完整流水线中。

若目标是精确理解算法，应先读本站 [子词分词专题](../subword-tokenization/index.md) 的公式、手算和官方代码，再回到书中观察 tokenizer 怎样影响整个 LLM 生命周期。

## 6. 对 CAT 的最终启发

生成式 CAT 不是把题目 token 化后让大模型一次输出一套题。它是多层系统：

```text
学生实时反馈
→ 可校准的状态更新
→ 内容与题库约束
→ 学习到的长期策略
→ 每一步重新决策
```

LLM 的优势主要在语义、内容、开放作答和解释；自适应性来自每步交互后的状态更新与策略重算。

## 7. 结论

这本书最值得保留的框架是：LLM application 由数据、模型和系统共同构成。任何一层的改进都可能被另一层的错误抵消。

```text
好模型 + 坏检索 = 无依据回答
好检索 + 坏生成 = 证据未被正确使用
好生成 + 坏权限 = 危险工具行为
好策略 + 坏测量 = 不可靠 CAT
```

系统设计的目标是让每一层的责任、证据和失败边界都可以单独检查。
