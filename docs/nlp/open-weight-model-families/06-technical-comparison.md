# 架构、上下文与部署的横向比较

## 1. 比较前先统一对象

比较模型时至少固定四项：基础或指令版本、模型日期、精确参数规模和推理精度。把 7B 指令模型与 100B 级基础模型放在一张准确率表中，结论很难解释。

下面选择各家族最能体现设计思想的版本，而非声称覆盖所有最新型号。

| 维度 | Command R | Mistral / Mixtral | Phi | Llama |
|---|---|---|---|---|
| 主要形态 | decoder-only，指令与 RAG 优化 | decoder-only dense 与 sparse MoE | 小到中型 decoder-only，并扩展多模态与推理版本 | decoder-only dense，后续扩展 MoE 与多模态 |
| 代表效率技术 | GQA、长上下文 | GQA、SWA、sparse MoE | 小参数规模、数据筛选、量化部署 | GQA、长上下文、后续 MoE |
| 明确强化的能力 | grounded generation、引用、工具调用 | 通用生成、代码、本地部署、MoE | 小模型推理、端侧与成本效率 | 通用基础能力、对话对齐、广泛生态 |
| 权重开放特征 | 研究权重，常带 NC 限制 | 按检查点变化 | 多个官方版本为 MIT | 自定义社区许可证 |

## 2. Dense 与 MoE

Dense Transformer 对每个 token 使用同一组前馈参数：

\[
h'=\operatorname{FFN}(h).
\]

MoE 让路由器选择少数专家：

\[
h'=\sum_{e\in\operatorname{TopK}(g(h))}g_e(h)E_e(h).
\]

MoE 可以增加总容量而不过度增加单 token 计算，部署时要同时报告：

- 总参数；
- 每 token 激活参数；
- 专家数和 top-\(k\)；
- 所需设备数与通信方式。

只写“17B active”会低估权重驻留和跨设备成本。

## 3. 长上下文与 RAG

长上下文和 RAG 可以互补：

```text
RAG：从大语料库中筛选相关片段
长上下文：在一次推理中容纳更多候选证据与历史
```

若把所有文档直接放进长上下文，输入成本和注意力干扰都会增加。若只依赖检索，召回失败会让生成模型看不到答案。实际系统通常先检索和重排，再利用长上下文综合有限数量的证据。

Command R 的训练更加显式地面向此流程；其他家族也能通过提示、微调和工具框架执行 RAG。差别应由引用正确率、拒答率和端到端延迟验证。

## 4. 小模型与大模型的成本结构

一次部署成本至少包括：

\[
C_{	ext{total}}
=
C_{	ext{weights}}
+C_{	ext{prefill}}
+C_{	ext{decode}}
+C_{	ext{KV}}
+C_{	ext{serving}}.
\]

- Phi 的小参数规模主要降低权重和解码成本；
- GQA 主要压缩 KV cache；
- SWA 主要降低注意力连接成本；
- MoE 主要控制每 token 激活计算，但仍需要保存大量总权重；
- RAG 会增加检索、重排和输入 token 成本，却可能提升知识时效性和可追溯性。

## 5. Base、Instruct 与 RAG 专门化

| 类型 | 训练状态 | 更适合 |
|---|---|---|
| Base | 主要完成预训练 | 继续预训练、领域适配、机制研究 |
| Instruct / Chat | 加入 SFT 和偏好对齐 | 直接对话、任务遵循、产品原型 |
| RAG / tool optimized | 专门训练文档格式、引用或工具轨迹 | 企业检索、agent 与 grounded generation |

对 base 模型直接使用聊天提示通常不是公平评价；对已经对齐的 chat 模型继续训练时，也要防止灾难性遗忘其指令与安全行为。

## 6. 推荐的统一测评矩阵

选型实验至少覆盖：

| 指标组 | 例子 |
|---|---|
| 任务质量 | 准确率、F1、代码测试通过率、人工偏好 |
| 可靠性 | 幻觉率、拒答率、引用精确率与召回率 |
| 多语言 | 每种目标语言分别报告，不做简单平均掩盖弱项 |
| 系统成本 | 首 token 延迟、tokens/s、峰值显存、并发吞吐 |
| 稳健性 | 提示变化、长上下文位置、对抗文档、工具失败 |
| 治理 | 许可证、数据驻留、日志与审计能力 |

最终选择应建立在同一硬件、同一量化、同一提示模板和同一业务数据上的对照实验。
