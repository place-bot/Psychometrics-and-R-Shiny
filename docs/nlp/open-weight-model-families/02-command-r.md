# Command R：围绕 RAG 与工具使用设计

## 1. 家族定位

Command R 不是单纯追求通用排行榜分数的基础模型系列。Cohere 把它的训练重点放在企业应用常见的三条链路：

1. 从外部文档中检索证据；
2. 基于证据生成带引用或可追溯的答案；
3. 调用一个或多个工具完成任务。

这使 Command R 更适合放在 RAG 系统或 agent 流水线中理解。

```text
用户问题
   ↓
查询改写 / 检索
   ↓
文档片段 + 元数据
   ↓
Command R grounded generation
   ├── 生成回答
   └── 将回答片段对应到证据
```

## 3. Grounded generation 怎样工作

普通语言模型学习：

\[
p(y\mid x),
\]

其中 \(x\) 是用户提示，\(y\) 是回答。RAG 场景向输入加入检索文档 \(D\)：

\[
p(y,c\mid x,D),
\]

其中 \(c\) 表示回答与证据位置之间的引用关系。理想模型需要同时满足：

- **相关性**：回答问题本身；
- **忠实性**：关键陈述可以由文档支持；
- **可归因性**：引用指向真正支持该陈述的片段；
- **拒答能力**：文档不含答案时不过度补全。

长上下文只能提高一次输入能够容纳的文档数量，不能自动保证证据相关、引用正确或答案无幻觉。检索质量和文档切分仍然决定系统上限。

## 4. 工具使用与多步 agent

工具调用可以写成一个循环：

\[
s_t=(x,h_{<t},o_{<t}),
\]

\[
a_t\sim p_\theta(a\mid s_t),
\]

其中 \(h_{<t}\) 是此前对话，\(o_{<t}\) 是工具返回结果，\(a_t\) 可以是自然语言回复或结构化工具请求。执行工具后得到 \(o_t\)，模型再决定下一步。

Command R+ 的模型卡强调 multi-step tool use，意味着训练目标覆盖“调用工具—读取结果—继续规划”的多轮过程。实际系统仍要在模型外部加入：

- JSON schema 校验；
- 权限控制与参数白名单；
- 最大调用步数；
- 超时、重试和人工确认；
- 对工具返回内容的提示注入防护。

## 5. 多语言能力怎样解读

Command R 08-2024 的模型卡称训练覆盖 23 种语言，并在其中 10 种语言上评价。两者含义不同：训练语料包含一种语言，不等于该语言获得了同等强度、同等任务范围的验证。中文 RAG 项目需要单独评测中文检索召回、引用边界和长文档问答。

## 6. 适用与限制

适合优先试验的场景包括企业知识库问答、带证据的研究助手、多语言客服与工具编排。主要限制包括：

- 32B、35B 或 104B 权重的本地部署成本较高；
- CC-BY-NC 研究权重不能直接视作通用商业许可证；
- RAG 能力依赖指定聊天模板和文档格式；
- 模型输出的引用仍需自动验证；
- API 产品和开放权重版本可能具有不同版本号与能力。

因此，选择 Command R 的核心理由应是“需要经过专门训练的检索、引用和工具行为”，同时把许可证与部署方式作为独立决策。
