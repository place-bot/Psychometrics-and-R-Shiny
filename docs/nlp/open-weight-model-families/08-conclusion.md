# 结论、局限与持续更新

## 1. 四个家族的技术主线

- **Command R** 把 RAG、引用和工具调用放到训练目标中心；
- **Mistral** 展示 dense、局部注意力、GQA 和 sparse MoE 的效率组合；
- **Phi** 研究高质量与合成数据怎样提高小模型的能力密度；
- **Llama** 形成覆盖预训练、对齐、微调、量化与部署的广泛开放权重生态。

它们可以在同一项目中互为候选，也可以承担不同角色。例如，用小型 Phi 进行本地分类，用 Command R 处理带引用的知识库问答，再用 Llama 或 Mistral 完成需要更强通用生成的部分。

## 2. 最重要的术语结论

“可调用”“代码公开”“权重可下载”“允许商用”“训练可复现”是五个不同问题。模型品牌也不是许可证。准确写法应始终包含具体检查点与许可状态。

## 3. 本专题没有解决的部分

- 没有穷尽 2026 年所有日期版本和区域性 API 别名；
- 没有对四个家族进行统一硬件上的重新跑分；
- 许可证说明用于研究与工程初筛，不构成法律意见；
- 官方披露的训练数据细节不同，无法进行完全对称的数据来源比较；
- 同一家族的 base、instruct、reasoning 和 multimodal 版本能力不可互换。

## 4. 持续更新模型卡的方法

每次更新只追加“最新模型”会让页面迅速失去结构。更稳妥的维护方法是：

1. 保留稳定的比较维度：架构、数据、对齐、上下文、部署与许可证；
2. 每个家族选择解释范式变化的里程碑版本；
3. 对快速变化的产品列表只链接官方模型总览；
4. 给所有精确数字附上模型卡日期或版本；
5. 旧版本退役时保留其学术作用，并注明服务状态；
6. 将新型号放入同一评测协议，而不是直接接受供应商之间不可比的排行榜。

这样阅读者既能理解模型为什么这样设计，也能在未来版本出现后继续使用同一套分析框架。
