# 开源代码、开放权重与开放训练

## 1. “模型开放”至少包含六层

讨论软件时，“源码是否公开”常常足以形成初步判断。现代语言模型还包含权重、数据、训练方法、许可证和服务接口，因此需要分层查看。

| 层次 | 需要检查的对象 | 它允许我们做什么 |
|---|---|---|
| 模型接口 | API、网页或 SDK | 调用模型，但通常无法检查或修改权重 |
| 推理代码 | Transformer 实现、采样代码 | 理解和运行架构，前提是能够取得兼容权重 |
| 模型权重 | 参数张量与 tokenizer | 本地推理、量化、微调或继续训练 |
| 训练代码 | 预训练、SFT、偏好优化流水线 | 研究训练过程，但仍需要数据与算力 |
| 训练数据 | 数据来源、配比、过滤规则或完整语料 | 评估数据偏差并提高可复现性 |
| 许可证 | 代码许可、权重许可、可接受使用政策 | 决定研究、商用、再分发和衍生模型的法律边界 |

一个模型可能开放推理代码和权重，但只披露训练数据的类别；也可能提供 API 和技术报告，却不提供权重。把这些情况统一称为“完全开源”会丢失最重要的信息。

## 2. 三个实用术语

### Open-source software

通常指源代码依据开源许可证发布。这里描述的是软件，例如 tokenizer、推理服务器和训练框架。代码许可证不能自动覆盖模型权重。

### Open-weight model

指参数权重可以下载。该术语只说明权重可获得，并不自动意味着：

- 可以用于任何商业场景；
- 可以自由再分发；
- 训练数据公开；
- 完整训练代码公开；
- 满足某个严格的开放源代码定义。

### API-access model

用户通过服务接口发送输入并获得输出。API 便于快速使用和统一维护，却无法提供本地权重控制，价格、数据治理与版本稳定性也由服务条款决定。

## 3. 为什么必须落实到具体检查点

“Mistral”或“Command”是家族名，不是一份许可证。以 Mistral 为例，早期 Mistral 7B 和 Mixtral 8x7B 权重采用 Apache 2.0；同一公司的其他模型可能使用研究许可证或仅以托管服务提供。Cohere 的 API 产品名称与 Cohere Labs 的开放权重研究版本也不能直接互换。

因此，许可证判断的最小单位应写成：

```text
发布组织 / 精确模型 ID / 日期或版本 / 权重许可证 / 代码许可证
```

例如：

```text
CohereLabs/c4ai-command-r-08-2024
权重：CC-BY-NC，并受可接受使用政策约束
```

这比“Command R 是开源的”提供了可执行信息。

## 4. 项目开始前的核对清单

1. 精确记录 model ID、revision 和 tokenizer revision；
2. 分别读取权重仓库的 LICENSE、模型卡和可接受使用政策；
3. 判断是否允许商业使用、托管服务、再分发和衍生模型；
4. 检查输入输出数据是否可以离开本地环境；
5. 核对上下文长度、量化支持、硬件需求和聊天模板；
6. 保存评测版本，避免供应商静默升级造成结果漂移。

许可证内容会发生变化。本专题提供技术阅读框架，实际法律判断应以目标版本的正式条款为准。
