# 怎样选择：任务、算力与许可证三条线

## 1. 从任务链路开始

### 企业知识库与可追溯问答

先测试 Command R 的 grounded generation，也要把 Mistral、Phi 或 Llama 配合统一 RAG 框架作为基线。核心指标是引用是否真正支持答案，而非只看自然语言流畅度。

### 本地、离线与端侧运行

优先从 Phi mini、小型 Llama、Ministral 或 Mistral 7B 级模型开始。先确定设备的可用内存、上下文长度和并发数，再选择量化精度。

### 高吞吐通用服务

比较 dense 模型的批处理效率与 MoE 模型的设备通信成本。参数排行榜不能代替真实服务压力测试。

### 领域继续训练

需要确认是否有 base checkpoint、tokenizer 是否稳定、许可证是否允许衍生模型与再分发，以及训练框架能否完整加载该架构。

### 工具型 agent

比较工具调用 schema 正确率、参数填充正确率、失败恢复、多步完成率和不必要调用率。Command R 的专门训练是有意义的候选起点，其他家族的 instruct 版本也应在相同 agent harness 中测试。

## 2. 一个可执行的漏斗

```text
许可证和数据治理硬约束
        ↓ 过滤
硬件、延迟和上下文预算
        ↓ 过滤
目标任务离线评测
        ↓ 排序
小规模真实流量 / 人工盲评
        ↓
部署、监控与回滚
```

先应用硬约束可以避免在不可能上线的模型上花费大量评测资源。

## 3. 许可证决策表

| 问题 | 若答案为“是”要检查什么 |
|---|---|
| 产品会收费或用于公司内部业务吗？ | 是否允许商业使用；NC 条款通常需要额外授权 |
| 会把权重或 adapter 发给客户吗？ | 再分发、归属、许可证副本与命名要求 |
| 会用输出训练另一个模型吗？ | 输出使用和模型改进条款 |
| 服务月活规模很大吗？ | 自定义社区许可证中的规模门槛 |
| 会在医疗、教育评分或金融等高风险领域运行吗？ | 可接受使用政策、行业法规和人工复核 |

## 4. 显存粗算

设模型参数量为 \(P\)，权重位宽为 \(b\)，仅权重理论占用为：

\[
M_{\text{weights}}=P\frac{b}{8}.
\]

例如 7B 模型：

| 精度 | 仅权重理论值 |
|---|---:|
| BF16 / FP16 | 约 14 GB |
| INT8 | 约 7 GB |
| INT4 | 约 3.5 GB |

部署还要加入 KV cache、运行时 workspace、激活和量化元数据。长上下文和高并发可能让 KV cache 超过权重节省，因此必须用目标批量和序列长度实测。

## 5. 一个最小评测协议

1. 固定 200–1000 个代表性业务样本，保留困难子集；
2. 固定 system prompt、检索结果与工具定义；
3. 每个模型使用其官方聊天模板；
4. 分别测试原精度和计划部署的量化精度；
5. 报告平均值、失败类型和置信区间；
6. 对开放式回答进行匿名随机排序与双人复核；
7. 保存 model revision、依赖版本、随机种子和完整输出。

## 6. 对教育与 CAT 研究的启发

如果将这些模型用于 CAT，模型家族选择应服从测量目标：

- 题目内容编码可使用小型 Phi 或 Llama 表征模型，但需验证测量不变性；
- 题库文档检索与依据说明可测试 Command R 式 grounded generation；
- 本地安全部署可以比较小型 Mistral、Phi 和 Llama；
- 生成题目或解释时应将项目参数、内容蓝图和审核规则放在模型外部约束；
- 任何 LLM 都不能凭语言流畅度替代题目校准、曝光控制、公平性与效度证据。

模型是 CAT 系统中的内容理解或策略组件，最终测量质量仍需通过学生反应数据验证。
