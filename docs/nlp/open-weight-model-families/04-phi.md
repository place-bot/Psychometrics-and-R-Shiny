# Phi：以数据质量提升小模型能力密度

## 1. 核心研究问题

Phi 系列围绕一个持续问题展开：如果训练数据经过严格筛选、合成和课程式组织，较小模型能否在推理、代码和通用语言任务上获得很高的单位参数能力？

常见规模路线可以概括为：

```text
Phi-1 / Phi-1.5
  强调 textbook-quality 与合成数据
        ↓
Phi-2
  扩展数据混合与通用能力
        ↓
Phi-3 / Phi-3.5
  端侧友好、长上下文、多语言与多模态分支
        ↓
Phi-4 家族
  14B 基础能力、推理模型、mini 与多模态版本
```

## 2. “Textbook-quality data”指什么

互联网语料数量巨大，但包含重复、残缺、噪声和缺乏教学结构的内容。Phi 的研究路线提高以下数据的比例：

- 逻辑清楚、概念逐步展开的文本；
- 经过过滤的高质量网页和代码；
- 由更强模型生成并经过规则或模型筛选的合成示例；
- 针对推理、数学与代码能力设计的任务数据。

可以把数据选择写成加权经验风险：

\[
\mathcal L(\theta)
=
\sum_{i=1}^{N}w(x_i)\,
\ell\bigl(f_\theta(x_i),y_i\bigr),
\]

其中 \(w(x_i)\) 表示样本的质量、目标相关性或课程阶段权重。提升数据质量不是简单删除低质量文本，还包括决定模型应先学哪些概念、用什么难度分布重复练习。

## 3. 合成数据为什么可能有效

合成数据能够精确控制：

- 题型与知识点覆盖；
- 推理步骤长度；
- 正反例比例；
- 语言和输出格式；
- 困难样本的密度。

但合成数据也会继承教师模型的偏差和错误。若训练集大量来自同一生成器，学生模型可能学习教师特有的表达模板，甚至在评测集附近产生污染。可靠流水线需要生成、过滤、去重、真实性检查和人工抽查，而非只扩大合成样本量。

## 4. Phi-3 与小型部署

Phi-3-mini 是约 3.8B 参数的模型，官方提供 4K 和 128K 上下文版本，并发布 ONNX、量化和跨平台部署选项。小模型的实际优势来自多项成本共同下降：

\[
\text{memory for weights}
\approx
P\times b/8,
\]

其中 \(P\) 是参数量，\(b\) 是每个参数的位数。3.8B 模型采用 4-bit 权重量化时，仅权重理论下限约为 1.9 GB；运行时还要加入 KV cache、激活、量化元数据和框架开销。

因此，参数量小为端侧运行创造条件，但不能只用上述理论值判断设备是否足够。

## 5. Phi-4 的数据路线

Phi-4 是 14B dense decoder-only 模型。官方模型卡和技术报告把数据质量作为训练配方中心：预训练混合包含合成数据、筛选的公开网页与代码，并在预训练后加入监督微调和直接偏好优化。官方模型卡报告约 9.8T token 的训练规模和 16K 上下文。

这里揭示了一个重要变化：小模型路线不等于小数据路线。模型参数较少时，仍可使用大规模、反复筛选和高度结构化的数据训练，从而把更多能力压缩进有限参数。

## 6. MIT 许可证与开放范围

Phi-3-mini 和 Phi-4 等多个 Microsoft 官方权重使用 MIT 许可证，商用与修改限制相对少。仍需分别核对：

- 精确检查点是否为 Microsoft 官方发布；
- 模型卡是否列出额外使用限制；
- 所用推理代码、量化转换和第三方数据是否另有许可证；
- 高风险领域是否满足应用层法规与测试要求。

## 7. 能力边界

Phi 适合资源受限、低延迟、离线处理、蒸馏教师或窄领域微调。小模型仍会在长尾知识、复杂工具规划、跨语言稳定性和高难开放推理上落后于更大模型。选择 Phi 时应关注目标任务的实测通过率，而不是把“单位参数能力强”直接换算为“所有任务都足够”。
