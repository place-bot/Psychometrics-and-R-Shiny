# BLEU 结果与长度分析

## 1. 主结果

| 系统 | All BLEU | No-UNK BLEU |
|---|---:|---:|
| RNNencdec-30 | 13.93 | 24.19 |
| RNNsearch-30 | 21.50 | 31.44 |
| RNNencdec-50 | 17.82 | 26.71 |
| RNNsearch-50 | 26.75 | 34.16 |
| RNNsearch-50* | 28.45 | **36.15** |
| Moses | **33.30** | 35.63 |

## 2. 配对增益

在相同最大训练长度下：

\[
21.50-13.93=7.57
\]

是 30 词模型在完整测试集上的提升；

\[
26.75-17.82=8.93
\]

是 50 词模型的提升。

No-UNK 子集对应提升为

\[
31.44-24.19=7.25,
\qquad
34.16-26.71=7.45.
\]

训练更久的 RNNsearch-50* 相对 RNNencdec-50 在 All 上高 10.63 BLEU，在 No-UNK 上高 9.44。

## 3. 与 Moses 的比较

完整测试集上，Moses 的 33.30 仍高于 RNNsearch-50* 的 28.45，差 4.85。No-UNK 子集上，RNNsearch-50* 的 36.15 略高于 Moses 的 35.63。

这表明封闭词表是当时神经系统的重要短板。No-UNK 子集排除了许多词表外问题，也改变了测试样本构成，因此不能据此宣称神经系统已在完整任务上超过 Moses。

## 4. 句长分析

论文按源句长度分组画出 BLEU 曲线：

- 固定向量 RNNencdec 随长度增加明显下降；
- RNNsearch 的曲线更稳定；
- RNNsearch-30 在长句上仍可超过 RNNencdec-50。

最后一点很关键：增加固定向量模型的训练句长没有消除瓶颈。动态访问源注释带来的信息路径变化，比单纯让基线见到更长训练句更有效。

## 5. 为什么动态上下文有利于长句

固定向量要求全部源信息穿过单个 \(\mathbf c\)。RNNsearch 对每个目标词建立较短路径：

\[
\mathbf h_j
\longrightarrow
\alpha_{ij}
\longrightarrow
\mathbf c_i
\longrightarrow
y_i.
\]

源句变长时，目标词仍可以直接访问相应位置的注释，不必依靠一个固定向量完整保存全部细节。

## 6. NLL 与 BLEU

表中的训练/开发 NLL 与 BLEU衡量不同对象：

- NLL 衡量模型给参考目标序列分配的概率；
- BLEU 衡量搜索后译文与参考译文的 n-gram 重叠。

概率建模、搜索策略、长度偏好和 \([UNK]\) 都会影响两者关系。较低开发 NLL通常有利于 BLEU，但不存在严格一一对应。

## 7. 结论强度

结果直接支持：

- RNNsearch 整体显著优于论文中的固定向量基线；
- 优势在长句上尤为明显；
- 词表外问题限制完整测试集表现。

结果尚未隔离：

- 双向编码器单独贡献多少；
- attention 单独贡献多少；
- 更长训练对星号模型贡献多少；
- 随机种子变化下增益的区间。

## 本页小结

最有说服力的证据由三部分共同构成：配对 BLEU 提升、长度曲线更稳定、长句译例保留更多细节。它们共同指向固定向量信息路径的局限。
