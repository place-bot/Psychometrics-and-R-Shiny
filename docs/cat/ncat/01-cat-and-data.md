# 问题、CAT 与离线数据

## 1. CAT 的基本对象

设题库为

\[
\mathcal J=\{q_1,q_2,\ldots,q_{|\mathcal J|}\}.
\]

学生的真实能力或知识状态记为

\[
\theta_i^0\in\mathbb R^d,
\]

它在短时 CAT 中通常被视为固定但未知。学生 \(i\) 对题 \(q\) 的二元反应记为 \(a\in\{0,1\}\)，其中 1 表示答对，0 表示答错。

响应模型 \(M\) 给出

\[
M(q\mid \theta_i)
\approx
\Pr(a=1\mid q,\theta_i).
\]

一次固定长度为 \(T\) 的 CAT 按以下顺序运行：

1. 从当前学生参数估计 \(\widehat\theta_i^{\,t-1}\) 和作答历史出发；
2. 选题算法选择尚未作答的题 \(q_t\)；
3. 观察学生答案 \(a_{i(t)}\)；
4. 用累计作答更新 \(\widehat\theta_i^{\,t}\)；
5. 重复到 \(T\) 步，或达到精度、时间等停止条件。

传统 IRT-CAT 常用 Fisher 信息、Kullback-Leibler 信息或后验方差等预先定义的 criterion。NCAT 令选题函数本身从数据中学习。

## 2. 三个容易混淆的学习对象

### 学生参数

\(\theta_i\) 是针对学生 \(i\) 的局部状态。每得到一个新答案，响应模型都可以重新估计它。

### 响应模型参数

题目难度、区分度、猜测参数，或 NCDM 的题目/知识点网络参数，是从大规模训练数据预先学到的全局参数。CAT 施测时通常冻结这些全局参数，只更新新学生的局部表示。

### 选题网络参数

\(\phi\) 是 NCAT 策略的全局参数。离线训练完成后，部署到新学生时通常冻结 \(\phi\)。策略仍具有适应性，因为它的输入状态 \(s_t\) 每一步都在改变。

!!! tip "参数冻结和自适应并不冲突"

    自适应来自函数输入的实时变化：

    \[
    q_t=\arg\max_{q\in\mathcal A_t} Q_\phi(s_t,q).
    \]

    即使 \(\phi\) 固定，学生刚刚的答案也会改变 \(s_t\)、合法动作集 \(\mathcal A_t\) 和所有候选题的排序。

## 3. 历史日志至少需要什么

最小作答记录可以表示为：

| 字段 | 例子 | 用途 |
|---|---:|---|
| `user_id` | 18 | 标识学生 |
| `exer_id` | 1370 | 标识题目 |
| `score` | 0 或 1 | 构造状态与读取离线答案 |
| `knowledge_code` | `[3, 11]` | 计算知识点覆盖、支持 NCDM |

正式研究还应保留时间戳、作答时长、题目版本、尝试次数、呈现位置、原 logging policy 与呈现概率。它们关系到重复作答处理、时间漂移和离线策略评估。

原仓库把一个学生组织为：

```json
{
  "user_id": 18,
  "log_num": 4,
  "logs": [
    {"exer_id": 2, "score": 1, "knowledge_code": [3]},
    {"exer_id": 7, "score": 0, "knowledge_code": [3, 11]},
    {"exer_id": 9, "score": 1, "knowledge_code": [11]},
    {"exer_id": 12, "score": 0, "knowledge_code": [5]}
  ]
}
```

## 4. 先按学生切分，再在学生内部切题

NCAT 使用两层切分。

### 学生级切分

论文进行 5 折交叉验证；每一折中的学生按 60%/20%/20% 分成训练、验证和测试学生。测试学生不会参与策略参数 \(\phi\) 的训练。

### 学生内部切分

对每个学生 \(i\)，将其历史作答题随机分为：

\[
\mathcal D_i^s \quad\text{support 集},
\qquad
\mathcal D_i^u \quad\text{query 集},
\qquad
\mathcal D_i^s\cap\mathcal D_i^u=\varnothing.
\]

论文使用约 70% support、30% query，并在每个训练 epoch 重新随机切分以减轻过拟合。

- support 中的题形成候选动作；策略选中后才允许读取相应历史答案；
- query 题从候选集中隔离，只评价当前学生参数能否泛化到未用于适应的题。

在第 \(t\) 步，已经从 support 中选出的记录为

\[
\mathcal D_i^s(t)
=
\{(q_1,a_{i(1)}),\ldots,(q_t,a_{i(t)})\}.
\]

当前合法动作集合为

\[
\mathcal A_i^t
=
\{q:(q,a)\in\mathcal D_i^s\}
\setminus
\{q_1,\ldots,q_{t-1}\}.
\]

## 5. 离线训练怎样模拟逐题反馈

假设历史日志中已知学生 \(i\) 对 100 道题的答案。训练时可以从中挑一部分作为 support，但算法不能提前把所有 support 答案塞进状态。

一次离线交互是：

1. 策略只看已揭示的作答历史；
2. 在尚未选择的 support 题中选 \(q_t\)；
3. 环境查询日志中 \(q_t\) 的历史答案 \(a_{i(t)}\)；
4. 将 \((q_t,a_{i(t)})\) 追加到状态；
5. 更新学生参数；
6. 在 query 集上计算预测损失并形成 reward。

这保留了 CAT 的信息时间顺序：未来答案在被选中之前不可见。

## 6. 训练环境和真实部署的对应

| 阶段 | 下一题答案来自哪里 | query 集的作用 | 是否更新策略参数 |
|---|---|---|---|
| 离线训练 | 历史日志 | 计算 reward、训练 \(Q_\phi\) | 是 |
| 验证/离线测试 | 历史日志 | 计算 ACC/AUC/BCE | 否 |
| 新学生部署 | 学生实时作答 | 不存在可见 query 真值 | 否 |

部署时并不需要 query reward。训练已经把“什么样的历史状态和动作通常带来更好的后续测量”压缩进 \(Q_\phi\)。

## 7. 原论文和公开代码的切分差异

公开仓库当前快照与论文实验协议并不完全一致：

| 项目 | 论文 | 公开仓库快照 |
|---|---|---|
| 学生级切分 | 60%/20%/20%，5 折 | `env.py` 中约 80%/10%/10% |
| 学生内 support/query | 70%/30% | `split_data(ratio=0.5)`，即 50%/50% |
| 最大测试长度 | \(T=20\) | shell 示例为 \(T=10\) |
| replay 容量 | 10,000 | `Train.py` 常量为 50,000 |

复现论文结果时应以论文协议为主，并把代码改动记录在实验配置中。复现仓库行为时则应精确报告 commit 和运行配置。

## 8. 离线支持域限制

历史学生没有作答过的题，在这个离线环境中没有可查询答案。因此候选集只能来自该学生真实作答过的 support 题。

这会造成一个重要边界：模型学习的是**历史可观察题目内的重排策略**。若旧系统很少向某类学生呈现某些题，NCAT 也缺少这些状态-动作的结果数据。

!!! warning "随机切 support/query 不能消除 logging-policy bias"

    随机切分只防止同一道题同时进入适应和评价。它不会创造旧策略从未收集的反事实答案，也不会自动修正题目呈现概率不同造成的偏差。离线结论仍需共同支持、倾向分数、OPE 或在线实验补强。

下一页将把这个环境写成[双层目标、MDP 与奖励](02-objective-and-mdp.md)。
