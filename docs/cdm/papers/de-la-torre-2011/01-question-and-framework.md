# 问题与框架全貌

## 论文面对的困难

2011 年以前已经存在多种 CDM：

- DINA；
- DINO；
- NIDA 与 R-RUM；
- LLM；
- LCDM；
- GDM。

它们使用的公式语言并不统一。有的直接写概率，有的写 logit，有的写乘法；研究者很难从公式表面判断：

- 两种模型是否表达了同一类反应规律；
- 多个项目能否分别采用不同 CDM；
- 一道题是否真的需要饱和模型；
- 一个简洁模型造成的拟合损失是否显著。

G-DINA framework 将这些问题放进同一套“概率、设计矩阵、约束矩阵”语言中。

## 从 DINA 的限制出发

若项目 \(j\) 需要 \(K_j^*\) 个属性，DINA 把全部 \(2^K\) 个完整属性模式压成两组：

\[
\eta_{j1}:
\text{掌握全部所需属性},
\qquad
\eta_{j0}:
\text{至少缺少一个所需属性}.
\]

同属 \(\eta_{j0}\) 的学生共享成功概率 \(g_j\)。这个假设很强，因为“缺一个属性”和“缺全部属性”可能对应不同的解题能力。

G-DINA 对项目 \(j\) 保留全部

\[
2^{K_j^*}
\]

个约化属性组，并分别估计成功概率。一个需要三个属性的项目因此有八个成功概率：

\[
P(000),P(100),P(010),P(001),
P(110),P(101),P(011),P(111).
\]

## framework 的四个部件

### 1. 饱和反应函数

每个约化属性组拥有自己的成功概率。identity-link G-DINA 将这些概率分解为截距、主效应和交互效应。

### 2. link function

论文讨论三种标度：

\[
P,\qquad \operatorname{logit}(P),\qquad \log(P).
\]

饱和时三种标度都可表示任意 \(2^{K_j^*}\) 个概率，因此具有相同拟合；施加约束以后，三者通常形成不同模型。

### 3. 估计与变换

MMLE 先估计

\[
\widehat{\boldsymbol P}_j.
\]

design matrix 再把它变换成 G-DINA、logit CDM 或 log CDM 的效应参数。某些约化模型可用加权最小二乘直接得到 MLE。

### 4. 项目层模型比较

限制矩阵 \(R_{jr}\) 表示约化模型必须满足的等式。Wald 统计量衡量估计结果偏离这些等式的程度。

## “逐题”是框架的关键粒度

框架允许同一测验中的不同项目采用不同反应过程。例如：

| 项目 | 可能过程 |
| --- | --- |
| 题 A | 必须同时掌握全部属性，适合 DINA |
| 题 B | 任一属性即可带来同等提升，适合 DINO |
| 题 C | 各属性贡献相加，适合 A-CDM |
| 题 D | 存在特殊交互，需要饱和 G-DINA |

论文因此把“选一个全测验通用模型”推进到“对每道多属性题检验一个可解释模型”。

## 论文的证据结构

论文包含三类证据：

1. **代数证明**：不同 CDM 是三种一般模型的约束形式。
2. **模拟研究**：检验 Wald test 的 Type I error 与 power。
3. **真实数据**：分析分数减法数据和 MCMI-III 临床数据。

论文没有系统比较属性分类准确率，也没有进行跨样本复现。结论的主要强度在模型表示、估计框架和项目层模型比较。
